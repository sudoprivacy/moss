## 对话性能

现场旧首句“你好”：21,109 输入 token、缓存零命中，预填充8.528秒，首文字9.345秒，聊天完成11.803秒。不是内存不足，也不是单纯 SSE 未及时刷新。

现实现纯问候绕过 LLM，普通咨询用专用 compact 对话，历史默认4096字节、完整请求上限12288字节，不恢复通用 Agent transcript。工具分类仍严格验证当前意图、参数、座位和真实接口结果；不从历史推断下发动作。真实 LLM 小样本请求约2.2k输入token（完整请求约8KiB），缓存命中后分类约0.55–0.75秒；早期无缓存独立请求1.297秒。最后 API 示例包含上下文/数据库/模型/TTS及本地上传包装：

| 请求 | 首文字 | 完成（含 TTS/本地上传） |
|---|---:|---:|
| 你好 | 42ms | 1406ms |
| 你好。 | 7ms | 8ms |
| 你是谁？ | 597ms | 2550ms |
| 帮我调整至办公模式。 | 639ms | 1606ms |
| 请查看当前座椅角度。 | 812ms | 2004ms |
| 请再查看当前座椅角度。 | 946ms | 2002ms |

这是实际模型接入当前 API 的功能/时延小样本；座位上下文、控制、广播和状态接口均为本地 mock，**不是生产端到端起播耗时或多座位P95**。8轮均生成成功，独立上传8次；前两轮音频摘要一致，Agent创建次数0、真实设备/广播调用次数0。状态用例核对了真实协议形状的 `position:40` 和空数据，中文使用已有协议格式化，不再让第二次模型请求把空状态编成“平躺”。`position` 是接口返回的百分比，不代表实际角度读数。

`scripts/cabin-live-smoke.ts` 可经 localhost SSH 转发重复此测试；参数说明在文件开头。它不读取生产应用配置或凭证，所有设备/上下文/广播 URL 固定为本机 mock。

## TTS 稳定性与质量

最终方案：单独的 `cabin-tts-server.py`，单线程串行生成，每次实际重置 seed42；中文 temperature0，其他已验语言0.9；top_p1、top_k50、repetition_penalty1.05。日语 ono_anna、韩语 sohee，其余 Vivian。模型仍为原 Qwen3-TTS-12Hz-1.7B-CustomVoice-8bit，未替换权重。

隔离18004/18005，12个文本覆盖10语言，每个重复两次；全部同文 WAV SHA-256 相同、24kHz/单声道/PCM16。中文短回执合成0.942–1.024秒、音频4.24秒；中文长句合成2.619–2.628秒、音频11.84秒；其他语言短句合成约0.95–1.28秒。双请求同时提交后仍与串行摘要相同（排队后的两请求约0.958秒和1.895秒）；重启后同一中文短句摘要仍相同。

所有样本执行了真实 ASR 回读。中文长短句及其他语言主体内容完整，未出现零温度日/韩曾发生的24–48秒循环/缺失后文；中文“稍候”被识别成同音“稍后”，韩语“도우미”被识别成“도움”。**这不等于逐字语音或主观音色全部验收**，韩语词差异需要听辨；ASR不能区分识别错误与发音错误，也不能证明跨文本说话人身份完全一致。

验证中排除的方案/缺陷：

- 单纯零温度：批内生成和串行仍产生不同波形；日/韩会退化，不能全局应用。
- 所有语言统一正温度：中文短回执回读首字出现差异，最终中文采用已验的零温度；保持串行消除批量变化。
- HTTP断连清理：Starlette取消监听可能吞掉Task.cancel，出现模型已结束但HTTP不返回。增加停止标志与100ms清理等待上限；远端真实依赖环境27项测试全通过，完整语种探针和8轮API联调均不再挂起。
- 长Markdown功能介绍：触发1024 token上限，被拒绝并未上传坏文件。现增加朗读纯文本转换，compact使用两句以内简短口语；同一功能介绍API用例已成功完成。
- token耗尽、非有限/空音频、错误PCM、超时均失败，不缓存、不上传坏文件；不靠增加max_tokens掩盖循环。原显示回复保留，朗读时去除Markdown标记。

## ASR 与内存

同主机小规模交叠测试：共用audio进程时ASR约1.240–1.271秒；TTS/ASR独立进程后约0.160–0.165秒，同时TTS约1.278–1.328秒。最终方案将ASR代理上游改到独立8005。仍共享GPU，未验证16座位负载的P95或吞吐；串行TTS会降低合成并发吞吐，有界队列满时明确失败，固定回执缓存可减少重复合成。

512GiB统一内存当时约431GiB空闲，无压缩/交换压力。没有增加容器内存、wired-memory比例或模型预留。LLM仅准备prompt-cache-size64候选，保留其他参数；该项是缓存条目数，不是会话数或命中保证，重启后仍需真实推理预热。
