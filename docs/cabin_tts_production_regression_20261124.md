# 生产中文问候 TTS 退化修复（2026-11-24）

## 证据与原因

14:02、14:03 的真实测试回复是 `XX，您好，请问有什么可以帮您？`。`XX` 来自后台脱敏姓名，现有称呼逻辑把它当作实际姓名加进了回复。此前隔离测试没有姓名，因此只验证了无此前缀的通用问候，未覆盖生产实际文本。

使用 Vivian/Chinese、temperature=0、seed=42 合成这16个字时，模型产生67.92秒不可识别音频，生成耗时约15.2秒。音频格式有效、token数低于1024，原有PCM/token检查未拦截。生成与实际上传对象的SHA256完全相同，排除了本次样本在上传时被替换的情况；下载真实已上传文件进行ASR回读为空。

相同生产文本与模型改为temperature=0.9后，约1.19秒生成4.64秒音频，ASR完整识别为“X X，您好，请问有什么可以帮您？”。这说明固定seed可以重复生成同样的坏结果；确定性和PCM合法性不等于语音可用性。中文零温度默认值需要撤销。

另有四次输入接口返回ASR_NO_SPEECH。日志没有保存这些请求的原始麦克风音频，不能据此认定麦克风故障，也不能把它们与TTS异常混为同一原因。

## 修改

- Qwen TTS默认统一temperature=0.9，继续使用固定seed和串行生成；推荐配置明确覆盖旧的temperature=0。
- 回复称呼过滤XX、星号脱敏姓名及明确占位符；保留正常姓名的原有称呼行为。
- gateway按文本长度限制异常音频时长：min(120, max(12, 字符数×0.8+6))秒。超限即丢弃并报错，不发送音频；它是异常时长保护，不是通用音质检测。
- 为生产67.92秒样本元数据和占位姓名增加回归测试，真实模型smoke支持脱敏姓名上下文。

## 验证

- Cabin后端312项测试通过。
- gateway28项测试在生产模型venv全部通过，无跳过。
- 修复镜像通过隔离容器运行真实服务，使用生产同样的XX/男性上下文，模型使用真实8000/8004，设备和上传接口在该测试中本地模拟。
- 两次问候回复均不含XX，上传音频时长3.28秒，生成及模拟上传完成约959/839ms，两次SHA256一致；普通身份介绍回复6.48秒，约2.18秒完成。
- 隔离测试容器和模拟HTTP服务在finally中清理；没有真实座位控制或广播调用。
- 以上验证不能替代UE实播、多座位P95或未保存原始音频的麦克风问题排查。
