# 短信模拟发送

用于在测试环境验证平台配置、组织登录策略、验证码登录及邀请注册，无需腾讯短信账号，也不会发送真实短信。

1. 使用平台超级管理员进入“平台配置 → 短信”。
2. 打开“启用服务”和“模拟发送（仅测试，不发送真实短信）”。模拟模式隐藏腾讯参数和凭据输入，已有凭据保留。
3. 保存配置并重启 Moss。刷新页面，确认显示“模拟发送已生效”。保存后尚未重启时，运行实例仍使用之前的发送方式。
4. 进入“Sudowork 系统设置”，选择需要测试的配置范围，将默认登录方式设置为手机验证码并保存。
5. 在 Sudowork 手机登录或注册页面请求验证码，在启动 Moss 的终端日志中找到：

   ```text
   [PhoneAuth] DEV DELIVERY — verification code for 138****8000 is 123456. Simulation mode: no SMS is sent. ...
   ```

   输入该次实际生成的六位验证码。`123456` 只是格式示例，没有固定万能验证码。

注册仍需目标组织的有效邀请码，并且该组织应允许短信登录。手机号、昵称、验证码和邀请码均按原流程验证；注册得到普通用户，Moss 初始密码仍为手机号。未注册的手机号应使用注册入口。

模拟模式只改变验证码的投递方式，验证码有效期、重发间隔、次数限制、一次性使用和组织登录策略继续生效。Moss 管理平台仍使用账户密码登录。

此选项是全平台配置，适用于所有组织。仅在测试环境启用；验证码会出现在服务端日志中。

要恢复真实发送，关闭模拟选项，补齐有效的腾讯参数和凭据，保存并重启。没有此选项的历史平台配置默认使用腾讯发送；模拟发送不会因腾讯接口失败而自动启用。

平台已经接管短信后，以平台配置为准，`server.json` 中的 `phoneAuth.delivery` 不再覆盖它。未接管的部署仍可显式使用 `phoneAuth.enabled: true` 和 `phoneAuth.delivery: "log"`。
