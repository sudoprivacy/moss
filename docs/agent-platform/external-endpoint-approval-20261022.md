# 外部智能体服务地址申请与审批

日期：2026-10-22。范围：Moss 原开发分支；不修改 Agent 执行契约。

## 操作方式

入口：智能体管理 → 专属智能体 → 外部托管 → 接入外部智能体。

- 选择已批准地址：填写 API Key，直接测试连接，成功后进入定义与授权。
- 组织管理员填写新地址：填写申请说明并提交；不发送 API Key，也不连接未批准地址。超级管理员切换到同一组织，在“服务地址申请”中批准或拒绝。申请人刷新审批状态后继续测试。
- 超级管理员填写新地址：填写批准说明和 API Key，点击“批准地址并测试连接”。批准只向当前允许列表追加地址。若连接失败，地址批准仍然保留，修正密钥后重试测试即可。
- 组织未启用时，组织管理员仍能提交申请。地址获批不会自动启用组织；超级管理员需在“配置接入范围”显式启用。
- 地址申请列表显示申请人、时间、用途、审批结果、审核人和说明，以及地址当前是否仍在允许范围内。每页最多 50 条。

地址格式继续要求 http(s) 固定 IP、路径 /v1；不支持域名、其他路径、用户名密码、查询参数或片段。地址批准与智能体授权发布是不同步骤。

## 服务端实现

新增 Moss 管理接口：

| 接口（前缀 /api/v1/external-agents/admin） | 权限 | 行为 |
| --- | --- | --- |
| GET /endpoint-requests?after= | 组织管理员 | 只读分页当前组织的申请 |
| POST /endpoint-requests | 组织管理员 | 提交 endpoint、reason；相同规范化地址的待审申请去重 |
| POST /endpoint-requests/review | 超级管理员 | 携带申请修订号和 policy_revision，批准或拒绝 |
| POST /endpoints/approve | 超级管理员 | 显式批准地址并更新策略，携带 policy_revision |

仅新增 external_endpoint_requests 表与索引，不搬移或删除现有任务数据。每个组织最多保留 1000 条申请、最多允许 20 个地址。请求表不接受 API Key 或调用者指定的组织、审批身份。历史拒绝记录保留，重新申请产生新记录。

申请、审批和原有策略更新使用同一个组织策略行锁；审批、追加地址及审计在同一事务内完成。并发修改返回 409，要求刷新后重试。不会覆盖其他地址或自动改变组织启用状态。历史已批准记录不能恢复后来撤销的地址；测试、接入与执行继续检查当前服务端策略。

## 后续操作

刷新正在运行的 Moss 页面后使用上述入口。管理员仍需核对实际 API 服务归属；审批地址本身不证明 Agent 的定义、远端版本及 API Key 属于同一应用。
