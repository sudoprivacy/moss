# 智能体成本与用量（AM-17）

管理员在 Moss → 智能体管理 → 智能体台账 → **查看成本与用量**，选择时间范围及正式任务／迁移评测，点击查询。支持按部门、平台或智能体汇总、查看任务与账单明细、导出 JSON。普通成员不能读取组织报表，切换组织后旧请求与旧报表被隔离。

## 计量来源

仅统计实际经过 `ExecutionModelGateway`、由 SudoRouter 返回并核验身份的账单。Provider 自报的 token 数、历史页面上的估算和未经过网关的直连用量不进入已核对额度。当前单位是 Router quota，不是人民币等货币；不同 Router 的额度分别展示，不自动换算或相加。

每次新调用记录配置的 Router 权威标识；数值账户 ID、token ID 和账单 ID 只在该权威内有效。资产名称与平台来自 Nexus 的已验证资产元数据，且必须匹配 IAM grant 的 metadata digest、组织、负责人和部门。负责人及部门采用调用时 grant 快照，部门名称仅为当前名称的显示。元数据读取失败或不匹配时保留缺失，不能改变调用的历史归属。旧记录不进行隐式回填／迁移。

## 统计规则

- 查询区间为毫秒时间戳，精确到秒，左闭右开，最长 31 天。账单依据 Router 时间归入区间；跨界的调用可以出现在相邻报表，其同一笔账单只属于一个区间。待核对的在途调用可能与多个区间相交，不能直接把各区间的调用数相加。
- 以 Router 权威＋账户＋账单 ID 去重；相同条目重放只统计一次。不同内容复用同一 ID，或不同调用复用同一 token／账单，返回冲突错误，不输出看似完整的总计。
- 已核对额度只是已核对部分的小计。未核对、结果未知、凭证未确认回收、缺少历史平台／Router 归属分别披露。无记录不表示企业零消耗。
- 正式任务和迁移评测分开查询。不存在模型网关记录的原平台任务不能据此声称已实现可信归因。
- 一次 SQL 查询读取一致的记录集合。每次最多 2000 条调用，超出则明确拒绝并要求缩短时间，不静默截断。SQLite/PostgreSQL 的组织及时间索引和查询语义一致。
- GET 只读取已持久化账单，不重新调用模型、不核对 Router、不更新任务、不发布版本、不刷新授权。后续显式核对操作产生的新账单会在下次查询中显示。
- JSON 导出采用白名单投影，包含任务/资产/负责人/部门、平台、模型、状态及账单标识。不包含提示词、回答、端点、原始 IAM/Router 凭据或 token 配置。

## API 与边界

`GET /api/v1/agent-inventory/usage?from=<epoch-ms>&to=<epoch-ms>&mode=run|evaluation`

沿用当前组织的活跃管理员身份与 `admin:users` 检查。组织来自登录上下文，不能在请求参数中覆盖。此接口是 Moss 管理投影，不增加或复制 IAM、Router 账单和共享 Task/Registry 契约。

本批验证覆盖真实 SQLite/PostgreSQL 的只读查询、组织隔离、边界时间、两种运行范围、重复／冲突账单、数值溢出、历史缺失、记录上限及客户端组织切换。真实环境和全量回归结果另附验收记录。AM-17 的报表能力不替代 AM-06/12 的各协议模型路径装配，也不代表完整 1.1 验收。
