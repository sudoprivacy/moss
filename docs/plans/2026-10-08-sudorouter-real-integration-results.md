## 接口适配

依据用户提供的 `token-api.md`，改用 `GET /api/user/tokens`、`PUT /api/user/token/status`、`PUT /api/user/token/quota`。用户创建、Key 创建、账户额度更新等既有接口保持不变。请求的调用者 ID 为管理员 `New-Api-User`，目标账户使用 `user_id`；不会混用。

- 列表读取 `data.data` 和 `count`；指定查询使用 `id`；校验目标归属、重复 ID 与完整性。分页未约定时不猜测参数。
- 启用状态映射为 `enable`，停用为 `disabled`。修改前按组织账户和 Token ID 确认归属。
- 有限 Key 调整传 `delta_quota` 和 `unlimited_quota: false`；拒绝给不限额 Key 执行有限额增减，拒绝会将余额减成负数的请求。
- 本地持久记录防止成功请求重复执行。真实增量接口没有远端幂等承诺，结果不确定时暂停该成员/服务 Key 后续限额调整，必须先核对，不能换请求 ID 重试。
- 通过账户状态补充 `parent_disabled`，保留成员自身停用、到期、限额耗尽状态；列表掩码不作为模型请求凭证。
- 单元测试替身跟随真实契约更新，额度重复调用会再次累计，用于验证 Moss 去重。实际联调不启动 Router 替身。

## 新日志查询接口接入补充

收到并实测供应方 `GET /api/log/query` 后，Moss 用量接口已切换到这条路由。管理员凭据仅用于 Moss 后端调用，客户端请求结构不变。

```http
GET /api/log/query?user_id=9882&type=consumption&page_num=1&page_size=20&order_by=created_at&desc=true&api_key_name=member-7e1ca447-8d32-45bc
Authorization: Bearer <Router administrator credential>
New-Api-User: 76
```

管理员查询组织全部消费时省略 `api_key_name`。普通成员的名称由可信组织/成员 Token 绑定查询获得，不接受浏览器传入；每条结果再次校验名称。Key 名称需保持唯一且稳定，名称重用/重命名可能影响历史日志归属；检测到缺失或同账户重名时拒绝成员查询。

真实接口验证：不限制类型返回 5 条（包含登录）；`type=consumption` 返回 2 条；按有限额成员 Key 名称过滤返回 1 条，无匹配名称返回 0 条。`page_num=1/2`、`page_size=1` 分别返回两名成员的消费，`page_num=3` 返回空数组且总数仍为 2。`cost=1` 对应 $0.000002。响应不含原始日志 ID/Token ID，Moss 根据已验证 Key 名称映射 Token ID，为列表生成展示 ID，不将其伪装为供应方记录主键。

运行中的 Moss 已重启并通过 8 个真实 HTTP 查询场景：管理员分页 1/2/3、成员本人查询/空页/伪造账户与名称参数、不限额成员查询、无消费邀请成员查询。普通成员即使自行传入其他账户或 Key 名称，仍只返回自己的 Token 282；管理员总数 2，两名消费成员各总数 1，邀请成员总数 0。新日志相关自动回归 15/15 通过，构建及修改文件 ESLint 通过，类型棘轮 104/105 通过。

全部角色的 `/api/v1/model-account/logs` 固定本人 Token。管理端指定成员通过 `/members/{id}/usage` 查询；不再因管理员身份将个人日志扩大到全组织。组织总余额仍仅在组织账户/充值入口显示。

新增后台充值和人工核对的服务、独立数据表及 Moss 操作界面；只复用既有 `PUT /api/user/quota`。真实 API 充值测试 $0.01，单号 `MADMf51ec7b767939f8577d34ada`，5000 quota 只发一次，成员限额不变。浏览器又完成一笔 $0.01 验证。富友重放不重复到账。

限额接口最终核验纠正了早期探针推断：**非零 delta 始终为增量，零 delta + 有限模式为清零。** 不能直接将新预算当成切换参数。最终采用先切有限并清零、再增加新预算；中间有短暂零额度窗口，部分成功/未知结果禁止重发。专用 Token286 在历史剩余 -1 时切回 $5，结算后读取2500000，used_quota保留且仍停用。需要上游原子设置绝对限额才能消除两步窗口；当前不承诺该能力。
